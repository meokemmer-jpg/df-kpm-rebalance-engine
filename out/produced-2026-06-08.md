# DF-KPM-Rebalance-Engine [CRUX-MK]

## Einführung

Die Dark Factory (DF) KPM-Rebalance-Engine ist eine kraftvolle Lösung zur Optimierung des Portfolio-Managements im Kontext der Kemmer-Investments. Diese Engine basiert auf einem bayesianischen Entscheidungsmodell, das optimale Rebalances für Trading-Kontexte berechnet und sicherstellt, dass alle Empfehlungen den strengen Compliance-Anforderungen von Variante D entsprechen.

## Zweck

Die KPM-Rebalance-Engine dient der Bereitstellung eines bayesianischen Yield-Managers für die Rebalance-Decisions im Portfolio. Sie nutzt die Kelly-Formel zur Berechnung optimaler Wetten und implementiert einen Anti-Drawdown-Mechanismus, um das Risiko von plötzlichen Verlusten zu minimieren. Zusätzlich überprüft der System jede Empfehlung anhand der Variante D-Grenzwerte, um Compliance-Standards einzuhalten.

## Architektur

### Bayesian-Yield-Manager für KPM-Rebalance-Decisions

Die Engine ist in mehrere Module unterteilt, die spezifische Funktionen erfüllen:

1. **`src/rebalance_engine_main.py`:**
   - Implementiert die bayesianische Entscheidungslogik.
   - Berechnet den Kelly-Fraktionsrechner für jedes Trading-Kontext basierend auf dem aktuellen Portfolio-Wert und gegebenen Risikofaktoren.

2. **`src/kpm_variante_d_helpers.py`:**
   - Enthält Funktionen zur Berechnung der Kelly-Fraktion.
   - Handhabt den Anti-Drawdown-Mechanismus, der eine sanfte Bremse bei einem Drawdown von 15% auslöst.

3. **`src/adapter_orchestrator.py`:**
   - Dies ist die Einstiegspunkt für LaunchAgent und organisiert den Ablauf aller notwendigen Prozesse.
   - Steuert die Kommunikation zwischen verschiedenen Modulen der Engine und dem externen System, wie das Portfolio-Management.

4. **`src/audit_logger.py`:**
   - Verwendet HMAC-SHA256 zur Generierung von Audits, um alle Aktivitäten des Systems zu dokumentieren.
   - Enthält Protokolle für jede Rebalance-Empfehlung und Operation, die durch den System ausgeführt wird.

### Sandbox-Default ohne Real-Trade-Execution

Die DF-KPM-Rebalance-Engine operiert standardmäßig in einer sandbox-Umgebung. Hier werden Empfehlungen generiert, aber keine tatsächlichen Handelsaktionen durchgeführt. Der Umstieg auf reale Transaktionen ist möglich, jedoch unter strengen Sicherheitsrichtlinien:

```bash
DF_KPM_REBALANCE_REAL_ENABLED=false # Standard
```

### CRUX-Bindung

- **K_0:** Die DF empfiehlt nur Rebalance-Aktionen und führt keine echten Handlungen aus.
- **Q_0:** Sorgt für konsistente Compliance-Empfehlungen gemäß Variante D-Anforderungen.
- **W_0:** Minimiert die Martin-Bandbreite durch Berechnung und Empfehlung von Rebalance-Aktionen im Voraus, ohne realen Handlungsbedarf.

## Funktionsweise

### Kelly-Fraction-Calculator pro Trading-Kontext
Die `src/rebalance_engine_main.py` implementiert eine bayesianische Entscheidungslogik, die auf der Kelly-Formel basiert, um optimale Wetten in jedem Handelskontext zu berechnen. Diese Logik berücksichtigt den aktuellen Portfolio-Wert und den gegebenen Risikofaktor.

### Anti-Drawdown-Soft-Brake
Eine grundlegende Bestandteil des Systems ist der Anti-Drawdown-Mechanismus, der eine sanfte Bremse bei einem Drawdown von 15% auslöst. Dies wird durch die Datei `src/kpm_variante_d_helpers.py` verwaltet und sorgt dafür, dass das System risikomindernd reagiert, wenn ein bestimmter Verlustniveau erreicht wurde.

### Konsens-Check mit Variante D-Limits
Der Check des Systems läuft auf der Überprüfung der Entscheidungen anhand von Variante D-Grenzwerten. Diese Prüfungen stellen sicher, dass alle Empfehlungen den strengen Compliance-Anforderungen entsprechen und innerhalb der vorgesehenen Grenzen operieren.

### Sandbox-Default ohne Real-Trade-Execution
Die DF-KPM-Rebalance-Engine operiert standardmäßig in einem sandbox-Umgebung. Hier wird nur eine Empfehlung an KPM generiert, aber keine tatsächlichen Handelsaktionen durchgeführt. Das Umstellen auf reale Transaktionen ist möglich, jedoch unter strengen Sicherheitsrichtlinien:

```bash
DF_KPM_REBALANCE_REAL_ENABLED=false # Standard
```

## Implementierungsschritte

1. **Initialisieren der Sandbox-Umgebung:**
   - Starten Sie den LaunchAgent in der sandbox-Modus.
   ```bash
   source activate sandbox
   python src/adapter_orchestrator.py --mode=sandbox
   ```

2. **Kelly-Fraction-Berechnung:**
   - Führen Sie die Kelly-Fraktion Berechnungen durch, basierend auf den aktuellen Portfolio-Status.
   ```python
   kelly_fraction = calculate_kelly_fraction(current_portfolio_value)
   ```

3. **Drawdown-Kontrolle:**
   - Überwachen Sie den Drawdown und aktivieren Sie die sanfte Bremse bei einer bestimmten Schwelle.
   ```python
   if current_drawdown >= 0.15:
       apply_soft_brake()
   ```

4. **Konsens-Überprüfung:**
   - Jede Empfehlung wird anhand der Variante D-Grenzwerte überprüft und genehmigt.
   ```python
   if recommend_action_within_dlimits():
       approve_recommendation()
   else:
       reject_recommendation()
   ```

5. **Generieren von Audit-Protokollen:**
   - Generieren Sie HMAC-SHA256-Audit-Logs für jede Rebalance-Empfehlung und Operation.
   ```python
   audit = generate_audit_log(action, context)
   write_to_audit_file(audit)
   ```

## Sicherheitsrichtlinien

Die DF-KPM-Rebalance-Engine folgt strengen Sicherheitsrichtlinien:

1. **Real-Trade-Aktivierung:**
   - Die Aktivierung von echten Transaktionen ist nur unter speziellen Umständen und mit expliziter Genehmigung möglich.
   ```bash
   export DF_KPM_REBALANCE_REAL_ENABLED=true
   ```

2. **Audit-Protokolle:**
   - Alle System-Aktivitäten werden über HMAC-SHA256-Audit-Logs dokumentiert.

3. **Compliance-Bestätigung:**
   - Jede Empfehlung wird vor der Generierung anhand von Variante D-Grenzwerten geprüft und genehmigt.
